# SourceSpool — project plans

Inspiration: Yoinks. Prepared 12 October 2026 (Asia/Singapore).

This folder contains seven phase files: product definition, design, implementation, GitHub release, an owner posting kit, planned easy npm installation (Phase 5.5), and planned Android APK support. Plans 1–4 are complete under the owner-approved solo-validation gate; see [execution evidence](docs/execution-status.md), the [public repository](https://github.com/JustinReyes28/sourcespool) and [v0.1.0 release](https://github.com/JustinReyes28/sourcespool/releases/tag/v0.1.0). Phase 5 is complete under the revised handoff gate: [captions and screenshots](docs/launch-kit/README.md) are ready for the owner to publish independently. Feedback collection and ongoing maintenance are outside Phase 5. Interviews remain deferred with assumptions explicitly unvalidated. Phase 5.5 is in progress: package and publish the Windows CLI to npm, add guided tool setup, verify installation without a source checkout, refresh release/social posting documentation, and reuse verified existing downloads to limit cellular data. Phase 6 is planned only: the owner selected a regular Android APK, and the engine, device testing and download budgets must be proved before support can be claimed.

## Read and execute in order

- **1. Product and differentiation:** validate a job, choose substantive new capabilities, and document inspiration/reuse.
- **2. Design, architecture, and GitHub:** define the workflow and storage, prepare the original scaffold, and create each product's separate repository during implementation.
- **3. Build and improve:** implement complete milestones and upload reviewable increments.
- **4. Validate and release:** test the actual product, run a small beta, and verify a versioned GitHub release.
- **5. Prepare the owner posting kit:** deliver accurate captions and screenshots for the owner to publish independently.
- **5.5. Easy installation and npm release:** support one-command launch/global installation, guided per-user tool setup, installed-package qualification and verified public npm publication; refresh the README/social posting kit and reuse verified existing downloads, with bulk online checks on hosted runners. Implementation and qualification are in progress.
- **6. Add Android support:** prove a native download engine, build a standalone phone APK, retain library/interchange behavior, qualify it on devices and publish a signed Android release. Implementation is not started.

Execution dates and approved gate amendments are recorded in the execution log. Phase 5 ends with delivery of the posting kit; public social posting is the owner's next action. Plans 5.5 and 6 are future implementation phases; writing these plans does not implement npm installation, publish a package, authorize SDK downloads or construct an Android app. Execute the installation phase before the Android phase.

## What makes the plans substantive

This project specifies three distinct capabilities, improvements to the core experience, a data model and component design, four build milestones, meaningful acceptance checks, a beta task, its own GitHub milestones, and tailored marketing drafts. Each keeps accurate upstream credit and a provenance register. Interface decoration alone is not the evidence of independent value; the implemented user workflow and its development records are.

## Publication boundaries

These phase plans originally scoped documentation only. The folder now contains the released production implementation and a separate design scaffold; consult the README for current behavior. Social copy matches the released v0.1.0 behavior. The owner will select accounts and destinations and publish independently; agent publication is outside the revised Phase 5 scope.
